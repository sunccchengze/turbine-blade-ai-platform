# D43 设计重构 Brief

## 用户决策

- 参考：Linear、Vercel、Claude。
- 第一优先级：A，项目科研可信度。
- 个人偏好：重视 B，页面要有记忆点和视觉冲击力。
- 不满意程度排序：A 不够高级 > E 页面不统一 > D 颜色/排版俗 > C 信息混乱 > B 不像工程软件。

## 设计立场

这不是“工业控制室主题皮肤”，也不是普通 AI SaaS 落地页。目标是一个有研究可信度的产品界面：安静、精确、留白足够，关键数字和证据边界比装饰更突出。

## 参考拆解

### Linear

借鉴约束感，而不是复制颜色：窄字重区间、细边界、紧凑但不拥挤的工作区、少量单一强调色。页面的高级感来自删掉多余元素，而不是增加发光和渐变。

### Vercel

借鉴黑白精度、强烈的版式层级、留白和“基础设施隐身”的克制感。页面不靠卡片数量证明功能，核心内容需要自己站得住。

### Claude

借鉴对话式、低摩擦、温和的阅读气质：让复杂的模型、指标和限制更容易被人理解。不要把科研平台做成冷冰冰的监控屏。

## 视觉系统方向

### Dark

- 温黑而不是蓝黑；
- 细灰边界而不是厚阴影；
- 青绿色为运行/可用状态；
- 暗金色只给主动作、Gate 和重点数字；
- 不再使用大面积紫色渐变。

### Light

- 暖白纸面而不是纯白 SaaS 背景；
- 墨绿色文字；
- 青绿与暗金保持同一语义；
- 线框、排版和留白保持 Dark 的几何关系。

## 信息架构优先级

每个页面首屏必须回答：

1. 这里是什么任务？
2. 当前数字/图表属于哪种证据？
3. 用户下一步能做什么？
4. 哪些结论仍然不能下？

## 页面改造顺序

1. App shell / Navbar / 主题系统
2. 首页：建立可信的产品叙事
3. Explore：建立核心工作区和流场视觉
4. Predict：建立输入、预测、UQ 的清晰层级
5. Optimize：建立候选、权衡、状态和证据标签
6. Methodology / UQ：建立可读的研究说明
7. Generate / About：收口一致性和项目时间线
