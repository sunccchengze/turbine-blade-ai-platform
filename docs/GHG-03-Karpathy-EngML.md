## 总体印象与工程定级

这是一个极度清爽的 AI Web 工作台架构：**没有笨重臃肿的后端服务器轮询，没有恶心的冷启动等待，直接利用 `onnxruntime-web/wasm` 在用户浏览器单线程/多线程 SIMD 中完成矩阵前向传播**。产物仅 13.4MB，构建仅 5 秒，极其优雅。

## 犀利挑刺与“找茬”清单

### 1. 【WASM 内存与单例 Session 缓存保护】
- **工程挑刺**：
  在 `frontend/src/utils/api.js` 中，`getSession()` 使用了全局 Promise 缓存模型实例。但在用户频繁在 `/predict`、`/explore` 之间快速切换路由时，若网络出现抖动（如慢速 3G 环境加载 `surrogate_model.onnx`），缺乏显式的重试机制（Retry Policy）。如果加载中途断网，Promise 会永久处于 Rejected 状态，用户不刷新网页就永远无法再次触发推理。
- **老卡修复建议**：
  - 在 `getSession()` 捕获错误时重置 `sessionPromise = null`，确保网络恢复后下一次调用可以自愈重试。

### 2. 【Explore 页面 2D 扫描网格评估的并发性能】
- **工程挑刺**：
  在 `Explore` 页面，当用户选择 $30 \times 30 = 900$ 个网格点并点击扫描时，前端会将 900 组 74 维向量打包为一个巨大的 Float32Array 传给 ONNX WASM。虽然单次批量推理耗时仅 15ms 左右，但在低端手机或老旧 CPU 上会造成主线程 50ms 的轻微卡顿（Jank）。
- **老卡修复建议**：
  - 在 `sweepDesignSpace` 批量推理前，增加 `await new Promise(r => setTimeout(r, 0))` 让出主线程微任务队列，确保前端的 `正在扫描…` 转圈动画能够立即渲染出来，消除掉帧感。

### 3. 【Predict 页面 74 维特征重置时的状态同步】
- **工程挑刺**：
  在 `Predict` 页面点击“重置基准 (Reset to Baseline)”时，虽然 `Omega`、`P` 等关键滑块恢复了基准值，但如果用户此前开启了 UQ 开关，重置后并没有在界面上给出一个平滑的“数值归位”视觉提示，数字直接硬变，缺乏确定性反馈。
- **老卡修复建议**：
  - 重置按钮触发时，给 3 大结果卡片一个持续 200ms 的轻微微光闪烁（Pulse），提示用户已完全回归 NASA Rotor 37 基准工况。

### 4. 【数据标准化防越界（Standardizer Clamping）的透明度】
- **工程挑刺**：
  模型在训练时对 74 维特征使用了标准差归一化 $z = \frac{x - \mu}{\sigma}$。在极端滑块输入下，某些衍生特征可能出现 $z > 5$ 的极端统计异常值。目前的前端虽然拦截了超范围输入，但没有向用户展示当前各个维度离训练集中心均值有多远（Mahalanobis 距离或 Z-Score）。
- **老卡修复建议**：
  - 在参数面板下方增加一个极小巧的 `分布健康度 (In-Distribution Metric)` 指示条：当所有参数处于 $\pm 2\sigma$ 内时显示绿色 `100% IN-DISTRIBUTION`；当有参数靠近边缘时动态提醒。
