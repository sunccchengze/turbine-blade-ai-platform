## 1. 产品定义

这不是普通的 Markdown 教材，也不是把文字放进一个矩形框里的“伪卡片”。

目标产品是：

> 一个有正反面、主动回忆、微型任务、项目映射、学习状态和复习路径的 HTML 学习卡片系统。

学习者每次只处理一张卡：

```text
情境 → 回忆 → 显示背面 → 公式/图示 → 微任务 → 过关反馈 → 下一张
```

每张卡必须完成三件事：

1. 能用自己的话解释一个概念；
2. 能完成一个极小的计算或判断；
3. 能说明它在 AI + 叶轮机械项目中的位置。

### 1.1 当前 18 张卡片主路线

| 阶段 | 卡片 | 目标 |
|---|---|---|
| 公式桥 | C01–C07 | 量、单位、比例、连续性、向量、导数、梯度、矩阵与网络 |
| 叶轮机械 | C08–C12 | 能量链、压力/温度、速度三角形、Euler 方程、级负荷与损失 |
| 证据闭环 | C13–C18 | 分离/失速、CFD/RANS、数据泄漏、代理模型、UQ、Pareto 与回灌 |

### 1.2 每张卡的固定节奏

| 时间 | 内容 |
|---|---|
| 0–1 分钟 | 只看正面，先回答问题 |
| 1–3 分钟 | 看直觉和情境 |
| 3–5 分钟 | 解释公式中的量和单位 |
| 5–8 分钟 | 完成微任务，不查答案 |
| 8–10 分钟 | 复述、评级、决定是否复习 |

## 2. GitHub 调研对象

调研时间：2026-09-16。重点查看 README、依赖、目录、测试、发布和公开 issue。

### 2.1 卡片产品与本地优先

#### Skola

项目：[h16nning/skola](https://github.com/h16nning/skola)

- React + Vite；
- Dexie.js / IndexedDB；
- FSRS.js；
- PWA；
- 本地优先，可选云同步；
- 双面卡、填空卡、富文本；
- 强调有实体感的 index card 视觉；
- 明确反对用 AI 代替学习者自己制作和思考卡片；
- 2026 年仍有维护，但项目自己标注仍处于早期阶段；
- 当前公开问题包括统计重构、Notebook 实验、准确率统计和授权说明。

**复用：** 卡片视觉、本地优先、离线、认知提示、内容和学习记录分离。
**避开：** 第一版不要账户、同步、富文本编辑器、复杂统计和卡片市场。

#### Vanilla Flashcard App Template

项目：[pedagogist/vanilla-flashcard-app-template](https://github.com/pedagogist/vanilla-flashcard-app-template)

- 纯 HTML/CSS/JavaScript；
- 无构建步骤；
- CSV 内容；
- 一个卡片一个卡片显示；
- Again / Good / Easy；
- localStorage 保存进度；
- 2026-05 仍有更新，但体量很小，只有示例级验证。

**复用：** 极简数据驱动卡片、明确翻面和本地进度。
**避开：** CSV 不适合公式/图示/证据；卡片点击翻面不利于可访问性；没有前置关系和项目映射。

### 2.2 复习调度

#### Anki

项目：[ankitects/anki](https://github.com/ankitects/anki)

- 30,000+ stars；
- 2026-09-15 发布 26.09.2；
- Rust、Python、Qt、TypeScript 混合；
- 真实用户规模和长期验证极强；
- 当前仍持续处理 MathJax 加载、预览性能、FSRS 模拟器等问题。

**复用：** 稳定卡片 ID、学习记录独立于内容、回忆评级、历史记录和媒体边界。
**避开：** 不搬运 Anki 的完整桌面端、同步、插件和卡片模板架构。

#### FSRS4Anki

项目：[open-spaced-repetition/fsrs4anki](https://github.com/open-spaced-repetition/fsrs4anki)

- MIT；
- 4,000+ stars；
- scheduler + optimizer；
- 根据真实复习历史估计记忆稳定性和复习间隔；
- 仍有 interval、插件兼容和参数优化相关 issue。

**复用：** 后续接入成熟 FSRS 实现，不手写“明天/三天后/七天后”的拍脑袋规则。
**边界：** “看过”不等于“回忆出来”。FSRS 评分必须建立在真实回忆反馈上。

#### AnkiDroid

项目：[ankidroid/Anki-Android](https://github.com/ankidroid/Anki-Android)

- 11,000+ stars；
- Kotlin；
- 2026-09-16 仍活跃；
- 移动端、同步、MathJax、语音、书写、统计和 FSRS 都有成熟经验。

**复用：** 移动端触控、离线、可访问性和内容类型边界。
**避开：** GPL/AGPL 许可和 Android 专用架构，不直接复制代码或 UI 资产。

### 2.3 漂亮的内容呈现与交互式教材

#### Slidev

项目：[slidevjs/slidev](https://github.com/slidevjs/slidev)

- 48,000+ stars；
- MIT；
- 2026-09-16 发布 v53；
- Vue 3 + Vite + UnoCSS；
- Markdown 驱动；
- KaTeX、Mermaid、Shiki、组件、动画、主题和导出能力。

**复用：** 内容与视觉分离、组件化、公式/图示、主题 token、适度动效。
**避开：** Slidev 是演示文稿运行时，不是带掌握度、复习状态和前置关系的学习运行时；不把当前 React 应用改成 Vue。

#### Math for AI

项目：[bendazz/math-for-ai](https://github.com/bendazz/math-for-ai)

- 2026-09-13 仍有更新；
- 小型 HTML/CSS/JavaScript 项目；
- 一个章节一个文件；
- Hash 路由；
- KaTeX；
- 练习题答案折叠；
- Canvas 小实验；
- 阅读宽度和排版较克制。

**复用：** 一单元一模块、答案默认隐藏、轻量数学实验、上一节/下一节导航。
**避开：** 全局 window、HTML 字符串拼接、CDN 公式、缺少类型和测试；生产版本用结构化数据和 React 组件。

#### mdBook

项目：[rust-lang/mdBook](https://github.com/rust-lang/mdBook)

- 22,000+ stars；
- Rust；
- 2026-09-15 仍活跃；
- Markdown → 在线书；
- 主题、预处理器、目录和静态构建成熟。

**复用：** 内容目录、静态内容构建、主题和预处理器思想。
**避开：** 它没有卡片翻面、回忆反馈和学习状态，不作为第一版运行时。

#### Jupyter Book

项目：[jupyter-book/jupyter-book](https://github.com/jupyter-book/jupyter-book)

- 4,000+ stars；
- BSD-3-Clause；
- 支持 Markdown、Notebook、代码执行、缓存、交叉引用、公式、网页和 PDF；
- v2 仍在发展，公开 issue 中有 v1/v2 指南和发布主题问题。

**复用：** 计算叙事、可复现附录、Notebook 实验、公式和引用体系。
**避开：** 第一版不引入 Python + Node 的完整构建链，不把卡片应用变成一本需要执行内核的书。

## 3. 技术选择

### 3.1 保留当前应用外壳

继续使用当前仓库已有的：

- React 19；
- Vite；
- Framer Motion；
- Tailwind CSS；
- Lucide；
- 当前暗色/浅色主题；
- 静态部署；
- 后续可复用 ONNX Runtime Web。

不引入新的大型前端框架，不另起 Vue、Slidev、Next.js 或独立 vanilla 应用。

### 3.2 卡片内容

卡片内容使用结构化字段，而不是把正文直接拼成 HTML 字符串。

每张卡至少包含：

- `id`；
- `order`；
- `phase`；
- `title`；
- `duration`；
- `prerequisites`；
- `front`；
- `back`；
- `intuition`；
- `formula`；
- `micro_task`；
- `answer`；
- `common_mistake`；
- `project_mapping`；
- `evidence`；
- `next_card`；
- `review_state`。

### 3.3 状态存储

**MVP：**

- 卡片内容静态打包；
- localStorage 保存掌握状态、尝试次数和更新时间；
- 无账户、无后端、无同步。

**第二阶段：**

- 卡片媒体和长期复习历史增多后，再使用 IndexedDB/Dexie；
- 真实复习数据稳定后，再接 FSRS.js；
- 云同步最后考虑。

### 3.4 公式和媒体

- 公式不能裸露原始 LaTeX；
- 公式分成“物理话、变量、符号、代数、数字例子”；
- 优先本地 KaTeX/MathML，避免首屏依赖 CDN；
- 图示使用本地 SVG；
- 不让公式引擎阻塞首屏；
- 图示不能成为唯一信息来源，必须有文字解释。

## 4. 视觉设计决策：Aero Atlas

### 4.1 总体语言

- 深海军蓝/墨绿色背景；
- 温暖纸张色卡片；
- 青色表示气流和速度；
- 琥珀色表示热量和能量；
- 铁锈红表示损失、风险和边界；
- 工程网格、纸张纹理、轻微噪点；
- 卡片有实体厚度、阴影和边缘；
- 不使用廉价玻璃拟态和过度霓虹。

### 4.2 一张卡的空间结构

```text
顶部：阶段 / 卡片编号 / 10 分钟 / 本地状态
主体：一个问题或一个情境
正面：只允许回忆，不提前显示答案
翻面：核心解释、公式、关键词、项目映射
微任务：单次计算或判断，参考结果默认隐藏
底部：需要复习 / 我能解释 / 上一张 / 下一张
侧栏：18 张卡片路线和完成状态
```

### 4.3 可访问性原则

- 不能只靠点击卡片翻面；
- 必须有明确的“显示答案”按钮；
- 支持键盘方向键、空格和返回正面；
- 支持 `prefers-reduced-motion`；
- 对比度合格；
- 触控区域足够大；
- 旋转后的隐藏面不能被屏幕阅读器误读；
- 动画不能承载唯一信息。

- 我能解释；
- 需要复习；
- 错误类型；

### 第 5 步：验收

- 首屏速度；
- 公式加载；
- 移动端；

## 7. 研究得出的关键教训

1. **卡片不是装饰。** 卡片正面必须触发回忆，背面必须完成解释和纠错。
2. **漂亮不能牺牲速度。** 公式、图片和动效不能阻塞首屏。
3. **翻面不能依赖鼠标。** 键盘、触控、屏幕阅读器都必须能完成流程。
4. **内容和状态必须分离。** 修改卡片正文不能破坏学习历史。
5. **先记录真实学习行为，再接复习算法。** 不提前假设 FSRS 能解决所有学习问题。
6. **本地优先适合个人科研学习。** 第一版不把账号、同步和后端带进来。
7. **公式必须逐层翻译。** 先物理话，再变量，再符号，再数字。
8. **不能把 Slidev/Anki/Jupyter Book 整体搬进来。** 借鉴经过验证的局部设计，保留当前 React 应用的控制权。
9. **当前仓库的 Rotor 37 代理模型仍是学习案例，不是工程真值。** 卡片中必须保留证据等级和验证边界。
10. **所有卡片都要连接下一张。** 不允许知识点变成孤立名词表。
