## 一、 核心公理与三要素模型

$$\mathbf{Agent = LLM + Context + Tools}$$

1. **LLM (推理引擎 / Policy)**：相当于 Agent 的“大脑”，负责根据当前信息做决策（“下一步做什么”）；
2. **Context (上下文工作集 / Observation Space)**：决定了 Agent 当前能看到的全部视野（短期会话、记忆检索、系统提示词、工具定义）。**上下文的质量与结构决定了 Agent 的智商上限**；
3. **Tools (行动接口 / Action Space)**：Agent 的“双手”，决定了 Agent 能对物理世界产生什么影响。代码执行（Code Interpreter）是最强大的元工具——它让 Agent 能够“现场创造出任意新工具”。

## 二、 关键架构设计原则

### 1. Harness 工程才是真正的护城河 (Beyond Model)
- 单纯依赖前沿大模型的基础能力很快会触碰天花板；
- 真正的工程壁垒在于包裹在模型外层的 **Harness**：
  - 任务前置引导与上下文预算分配（Context Budgeting）；
  - 确定性规则与 LLM 推理的混合编排（如阿里 OCR 架构）；
  - 失败拦截与自适应重试（Self-Correction Loops）。

### 2. 上下文工程的 4 大防御机制
- **静态前置缓存 (Prefix KV Cache)**：将稳定不变的宪章、色盘规范、数据契约置于上下文最前端；
- **动态工作集裁剪 (Working Context Pruning)**：避免将无用的历史报错持续堆积在 prompt 中；
- **结构化中间制品 (Structured Artifacts)**：使用 JSON / CSV / NPZ 替代冗长自然语言传递；
- **双向契约隔离 (Bidirectional Isolation)**：复杂子任务必须开辟干净独立的子 Agent 上下文。

### 3. 多 Agent 协作的拓扑结构
- **链式串联 (Chaining)**：适合顺序流水线（如：流场仿真 $\to$ 数据导出 $\to$ 图表绘制）；
- **主从分发 (Orchestrator-Workers)**：总指挥调度多个专注领域的工兵；
- **红蓝对抗 (Adversarial Evaluator)**：独立审查者拥有否决权，杜绝单模型自我安慰式交付。
