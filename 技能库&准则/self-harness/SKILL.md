# Self-Harness: 智能体运行时支架自演化引擎

> **核心哲学**：不换模型，换“用法”。模型的失败往往不是智能缺陷，而是 Harness（提示词约束、工具协议、记忆上下文、验证闸门）层面的失配。将 Harness 改进视为经验性的状态转换，通过闭环迭代释放模型真实上限。

---

## 一、 Self-Harness 三阶段执行闭环

```text
  ┌─────────────────────────────────────────────────────────────┐
  │                 1. 弱点挖掘 (Weakness Mining)                 │
  │  • 收集执行轨迹中的错误与用户批评                           │
  │  • 聚类为模型特异性失败模式 (Failure Pattern Clustering)    │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                 2. Harness 提案 (Harness Proposal)           │
  │  • 针对失败模式生成变动最小的配置补丁 (Minimal Patch)       │
  │  • 明确改变的行为、修改的表面 (Surface) 与可量化证据        │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                 3. 提案验证与晋升 (Validation & Promotion)    │
  │  • 运行回归测试 (Regression Test) 与对抗性检查              │
  │  • 仅采纳正向改善且无负面退化的提案，合并至主 Harness       │
  └─────────────────────────────────────────────────────────────┘
```

## 二、 本项目专属挖掘：四大已识别失败模式与针对性 Harness 补丁

### 失败模式 1：AI 模板腔与悬浮卡片惯性 (Template Slop Inertia)
- **根因分析**：模型生成排版时存在对前端框架（如 Tailwind UI/Notion 模板）的统计概率偏好，默认生成圆角卡片、Emoji 装饰与虚假二元对立。
- **Harness 补丁**：
  1. 激活 `Stop-slop.md` 与 `taste-skill`，强制前置规则检查；
  2. 强制在排版生成前调用真实物理数据与科学三线表规范，封杀纯修饰性卡片。

### 失败模式 2：物理几何与流场失真 (Physical Inconsistency)
- **根因分析**：模型将风机绘制为抽象圆圈气泡，丢失了叶轮实际偏航角 $\gamma$、尾流顺风/横向空间相对位置（$5D, 3D$）及真实风速梯度。
- **Harness 补丁**：
  1. 严禁使用绘图占位符，必须直接由 Matplotlib/FLORIS 提取真实 `.npz` 数据渲染 300 DPI 图像；
  2. 强制叶轮线条法向与偏航角严格对应。

### 开启与自检指令

当遇到复杂工科交付时，执行以下 Harness 自检流程：
1. **Pre-flight Audit**：检查当前输出是否命中已知失败模式；
2. **Execution Guard**：严格遵守发丝线、1.3 倍行距、真实物理流场；
3. **Post-execution Verify**：验证生成的交付物（PPTX / PSD / HTML）文件大小、图层完整性与无 AI 味指标。
